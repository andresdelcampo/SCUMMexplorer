# SCUMM room object states

Reconciled 8 October 2026. This reference separates the current interaction/rendering contract from the original old-v3 format evidence. LOOM EGA and CD/VGA use edition-specific data providers; the v3 byte offsets below do not apply to VGA archives. Current capability and remaining comparisons are in [the plan](../CURRENT_WORK.md) and [CURRENT_WORK](../CURRENT_WORK.md). The complete early implementation record is preserved in [the historical snapshot](../archive/SCUMM_OBJECT_STATES_BEFORE_RECONCILIATION_2026-10-08.md).

The image directory is an asset directory. Geometry or image order cannot establish which images belong to a story transition. Reached script state, positions, parent requirements and draw order feed the renderer; unresolved behavior and display-only estimates remain explicit.

## Current interaction and session contract

- In Interactive mode, a single click sends source input that walks/uses through the game's scripts; a double click also looks. Playback advances actors, camera, messages and scripts, and follows reached room loads. Inspection mode cycles stored artwork without changing the persistent session.
- Source touchability and responses govern navigation. A closed/untouchable exit cannot be forced through an ordinary click or doorway fallback. Advanced catalog browsing can still open a room as a disclosed exploration arrival. [Portal validation](../../.verification/portal-state-20261008/README.md).
- Single scene picks preserve the running session; stated sequences start fresh. Rooms normally use their earliest source entry state until reached scenes establish later state. On 8 October the user approved reviewed source prerequisites for direct late-room catalog starts. The fingerprinted English Room 46 recipe runs missing real scenes, preserves ghost/restored state and cancels the visit on failure. [Catalog return validation](../../.verification/catalog-return-20261008/README.md).
- Object state comes from the index and reached script operations. `SetState` changes the specified object; `DrawObject` applies source position changes and clears exact-bound peers. Parent-state requirements and room ownership govern active selection. Painting uses directory redraw plus the recorded draw queue; hit selection respects live script state.
- Display gap filling and provisional artwork do not assign persistent game state. Costumes persist until source changes them. No room-specific renderer preset, fabricated story flag or geometry-derived story transition is justified.
- A verified first visit means the settled state reached through the earliest normal game route. Catalog arrivals, direct verbs, explicit staff/note edits and seeded choices remain preview assumptions. Current bounded coverage does not prove every native input route, actor picture or audiovisual detail.

## Historical old-v3 format evidence

The following byte offsets, object IDs and counts belong to the supplied Spanish EGA audits of 27 September. They remain source evidence for that edition, not a fresh English/VGA inventory.

1. `00.LFL` starts with the `0x0100` signature and a global object count. Each object has three class bytes and one packed owner/state byte. The state is the high nibble. In the supplied LOOM index, objects 476–499 and 545–554 all have packed byte `0x0F`: owner 15, state 0. Thus the index alone would draw none of these images.
2. In old v3 rooms, byte 20 is the number of local objects. Image offsets and code offsets start at byte 29. The code records identify objects and their dimensions, position, parent, required parent state, walk-to coordinates, and facing direction. Some records have no distinct image; a run of entries can share an image pointer, with the final entry owning that image. `ScummRoomObjectDirectory` retains all valid code records, while `ScummRoomObjects` decodes only image-owning records.
3. The room entry script offset is the little-endian word at room bytes `0x1B–0x1C`. For the supplied rooms it is 31,388 in `28.LFL` and 14,750 in `33.LFL`. SCUMM runs global entry script, room entry script, then a second global entry script where configured. Those scripts can start others, branch on variables, and change object states.
4. An object is drawn when its state is nonzero and its parent state requirement is met. A room redraw (`drawRoomObjects`) paints active local objects in reverse room-directory order, so an earlier directory object covers a later overlapping one. `drawObject` does not paint immediately: it queues the object, and queued objects are painted on top of the redraw in call order (`processDrawQue`). `setState` marks the object's area dirty, which causes a redraw and clears that queue. Close-up faces (LOOM Rooms 56, 58, 86 and others) depend on this: the face image has colour-0 cut-outs that the eye or mouth images drawn after it fill, so directory order alone leaves black gaps. SCUMM `drawObject` explicitly clears the state of objects with **exactly** the same x, y, width, and height, then sets the requested object's state. `setState` changes only the specified object. `drawObject` can also move the requested object before comparing bounds. Neither rule says that overlapping images, shared bottom edges, or adjacent object IDs form variants.


## Display-only artwork estimates

The EGA selection implementation retains the following gap heuristic. It affects displayed artwork only; supported source state remains authoritative.

When an incomplete room visit leaves a **gap**, `FillGaps` closes it. A gap is a stored-image rectangle that is at least 90% colour 0 in the composite while the ring of pixels around it is at most 60% colour 0, and that has a stored image with at most 60% colour 0. The largest gap is filled first, so a container is chosen before the inserts in its cut-outs. It is filled by repainting an active image, else by applying the whole highest-priority `ScummSceneDrawBatches` batch that includes one of its images (a seeded pick among ties, seed = room number), else by a seeded random stored image. Batch priorities are 3 for the opening frame (the draws right after a script's *first* literal load of that room), 2 for the room entry script and 1 for all other scripts; a later load of the same room in the same script is a return, not an opening. When the visit leaves **no** script-visible artwork at all, the viewer also chooses a reproducible provisional image at each nonoverlapping position (`ShowUnresolvedArtwork`). Script-visible images take priority over every estimate; no room ID or object ID is hard-coded. These estimates exist only in the displayed room selection, not in the persistent SCUMM session. The UI labels their count and individual object entries. They are a useful early view when the interpreter cannot reach a state, but their combination is not proven by the game. Subsequent script actions replace this provisional view with reached state. The selection checks decoded parent-state requirements in session mode, so a child image is not rendered unless its parent chain matches.

## Historical supplied-EGA script evidence

- In `33.LFL`, the entry script starts at decoded offset 14,750. At 14,837 it tests bit variable `0x8D81`. One branch draws objects 551–554; the other draws 547–550. Later bytecode draws 545 and 546, whose exact-size peers are cleared by `drawObject`. This explains how the former manual arrangement could arise, but the branch value and the point at which the room should be sampled still depend on game execution. The script also starts other scripts and has multiple frame breaks. A list of image IDs alone is not a verified first-visit snapshot.
- In `28.LFL`, the entry script starts at decoded offset 31,388. Its early loops clear 483–489 and 476–482, then set 490–496 to state 1. Later drawing sequences for 483–489 and 476–482 are interspersed with actor commands and frame breaks. Thus 490–496 are a script-proven coherent early frame, but the stable post-entry view still requires running the remaining sequence. Selecting one image per black area would mix these sequences without evidence that they coexist at the same time.
- All 76 indexed rooms have embedded entry scripts. The sampled room objects in the global index start at state zero. A room-wide first-visit view therefore requires following script execution and persistent game variables; it cannot be recovered by initializing every object from the index or by filling black pixels.
