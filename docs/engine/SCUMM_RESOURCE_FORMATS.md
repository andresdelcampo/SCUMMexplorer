# SCUMM resource formats the explorer reads (beyond LOOM and Indy3 EGA)

Version scope is stated on every item. Everything here was checked against ScummVM's `engines/scumm` (resource, room, gfx, costume and palette sources) and against the local game data on 11 October 2026; pictures were checked in the real window (`.verification/generic-v4/README.md`). Only **rooms, costumes and sounds are read** for these games (plus, for v1/v2, the object pictures, below): their scripts and actors are not, so nothing here says what a script does (see [the script reference](SCUMM_SCRIPT_MAP.md) for the scope).

## Index and container layouts

| Layout | Games seen | Files | Index | Code |
|---|---|---|---|---|
| Classic v1 | Maniac Mansion, Zak McKracken (DOS EGA) | `00.LFL`…`NN.LFL`, every byte XOR 0xFF | magic `0x0A31`, one byte per global object, then directories of rooms, costumes, scripts and sounds whose **sizes are fixed per game and not stored** (Maniac 800/55/35/200/100, Zak 775/61/37/155/120); the game is the one whose sizes add up to the file length. A room directory is a skipped byte and a word offset per room; the others a room byte and a word offset per resource, `0xFFFF` = none. | `ScummV1Index` |
| Enhanced v2 | Maniac Mansion Enhanced, Zak McKracken Enhanced | same files, XOR 0xFF | magic `0x0100` (as old-v3), then one byte per object (old-v3 has four), then four directories (count, room bytes, word offsets) that end exactly at the end of the file | `LflIndexReader.DetectObjectEntryBytes` |
| Old v3 | LOOM EGA, Indy3 EGA | as above | magic `0x0100`, four bytes per object | `LflIndexReader` |
| v4, disks | Monkey Island (VGA 4 disks, EGA 8), LOOM CD (1) | `000.LFL`, `DISK01.LEC`…, LEC XOR 0x69 | tagged blocks `0R 0S 0C 0N 0O`; a resource is a room byte plus a dword offset counted from the first block inside that room's `LF` block | `ScummV4Archive`, `ScummV4Disks` |
| v5 | Indiana Jones and the Fate of Atlantis, Monkey Island 1 CD, Monkey Island 2 | `NAME.000` (index) and `NAME.001` (resources), XOR 0x69; on a CD in a language or game folder | blocks are a four-letter tag and a **big-endian** size counting its 8-byte header. Index: `RNAM` (room names), `MAXS`, directories `DROO DSCR DSOU DCOS DCHR DOBJ` (word count, a room byte per resource, a little-endian dword offset per resource). Resources: `LECF` holding `LOFF` (room number and offset of each room's first inner block) and the `LFLF` blocks (`ROOM SCRP SOUN COST CHAR`); a resource is at its room's `LOFF` offset plus its directory offset | `ScummV5Archive` |
| v4, room files | Indiana Jones and the Last Crusade, 256 colours | `00.lfl` (no XOR) with the same tagged blocks; `NN.lfl` is the content of one room's `LF` block (RO, SC, SO, CO) | same as v4 disks, offsets counted from the start of the room file | `ScummV4Archive.LoadRoomFiles` |

In every layout a room is the file `NN.LFL` (v1/v2/old-v3/room files) or an `LF` block of a disk (v4); a room of the directory that is not a picture (room 0 of the v2/v1 games is the index file; rooms 98 and 99 of Indy 256 are resource banks) is left out because its picture does not decode.

## Room pictures

| Format | Applies to | Description |
|---|---|---|
| Tiles | v1 | Header bytes 4 and 5 are the tiles across and down (8x8 pixels); word offsets at 10, 12, 14, 16 point at four run-length streams (`decodeV1Gfx`: four common bytes, then run codes): 256 character patterns of eight bytes (four 2-bit pixels, each drawn twice as wide), the character of each tile, a colour byte per tile and a mask character. Three room colours are header bytes 6 to 8, the fourth is the tile's colour byte & 7; the numbers are C64 colours that a per-game table turns into EGA colours. | `ScummV1RoomDecoder` |
| One stream | enhanced v2 | Width, height at bytes 4 and 6, picture at the word offset in byte 10: column by column, top to bottom; code = run of one colour (high nibble count, low nibble colour) or, with bit 7, a run repeating what the column to the left shows (a dither); zero count takes the next byte. Depth masks follow (not read). Height at most 128. | `ScummV2RoomDecoder` |
| Strips, EGA | old v3, v4 EGA (Monkey Island EGA) | The old-v3 strip code (run, copy-left, alternating pair); in v4 EGA the BM body is a length word, a word offset per strip (from the body start) and the strips. No `PA` block: the fixed EGA palette. | `ScummV3EgaRoomDecoder.DecodeStrip` |
| Strips, v5 | v5 | `ROOM` > `RMHD` (width, height, objects), `CLUT` (256 RGB; later versions `PALS` > `WRAP` > `APAL`), `RMIM` > `IM00` > `SMAP`: a dword offset per strip counted from the `SMAP` tag, then strips with the v4 codes plus the transparent twins 0x22-0x26 and 0x2C-0x30 (drawn as the plain ones) and the **major-minor** codes 0x40-0x44, 0x54-0x58, 0x68-0x6C, 0x7C-0x80 (row by row; first byte the colour; bit 0 keeps it, 10 sets a colour of `code % 10` bits, 11 and three bits minus four steps it, a step of zero repeats it for the next byte's count). | `ScummV4Archive.DecodeStrip`, `DecodeMajorMinorStrip` |
| Strips, 256 colours | v4, Indy 256 | Strip codes 0x01 raw, 0x0E-0x12 and 0x18-0x1C bit codes (v4); 0x02 runs, 0x03 four-bit codes, 0x04 local palette and runs, 0x07 stepped colour (older 256-colour games, ScummVM `unkDecode8`-`11`). Palette from the `PA` block. | `ScummV4Archive.DecodeStrip`, `DecodeOld256Strip` |

## Costumes and sounds

- **Costumes, v5.** The same layout as LOOM CD's costume (offsets count from 6 bytes before the body, which is two bytes into the 8-byte `COST` header), with 16 colours (format 0x58) or 32 (0x59: the palette is 32 bytes, so the command, limb and pose tables move up by 16, and a cel run is five bits of colour and three of count). Poses are drawn in the palette of the room that stores the costume.
- **Costumes.** v2 enhanced uses the old-v3 costume reader unchanged (format `0x58`/`0x59`, one colour byte). v4 costumes are read in the palette of the room that stores them (a pose's per-limb command index is a word in LOOM CD and a byte in the 256-colour Indy, where codes from 0x79 up draw nothing); a costume looks wrong where the game would set actor colours by script (Guybrush's shirt in room 10). v1 costumes (format `0x57`, `ScummCostumeRenderer.DecodeClassicV1Pose`): offsets are counted from byte 4 of the resource; the animation count is at byte 4, the animation commands at 4 + the word at 6, one frame-table word per limb from byte 8 (eight limbs), one animation word from byte 24; an animation is a limb mask byte (limb 0 = high bit) then a command index and a duration byte per limb (0xFF = none); a cel has a 6-byte header (width in 8-pixel units, height, x and y offsets in units of 8 pixels and pixels, then the movement to the next limb) and run-length bytes (bit 7: repeat the next byte) of four 2-bit pixels, each drawn twice as wide, column by column. Pixel 1 is the skin colour, 2 the suit colour, 3 black, 0 transparent; the C64 colour numbers go through the game's EGA table. **The actor's colours come from the game's scripts**: the explorer uses ScummVM's Maniac Mansion actor tables with the costume number as the actor number (an estimate) and a fixed colour for Zak.
- **Sounds.** v4 sounds are `SO` blocks holding a `WA` (PC speaker) and an `AD` (AdLib) block; the 256-colour Indy wraps them in a second `SO` block. **v2 sounds** (Maniac Mansion Enhanced, Zak McKracken Enhanced **and Zak McKracken classic**) are PC speaker data in the same player format as LOOM's old bundle (ScummVM `Player_V2`): a length word, priority and restart bytes, channel pointers from byte 6 (the first is 22, the others empty), and `ScummPcSpeakerAudio.RenderWave` plays them unchanged (checked 11 October: 59, 110 and 112 sounds render in Maniac Enhanced, Zak classic, Zak Enhanced). **Maniac Mansion classic** sounds are ScummVM's `Player_V1` format (`ScummPcSpeakerV1Audio`): length word, priority byte at 6 (bit 7 restartable), then from byte 10 chunks, each a type word and its words: 0 notes (tick length; then duration and divisor pairs, 0xFFFB escapes a word), 1 frequency sweep, 2 and 3 tick-length sweeps (3 with a noise mask), 0xFFFE sets the repeat point, 0xFFFD jumps to it, 0xFFFF ends. A tick lasts `mplex` cycles of the 1.193 MHz timer. 61 of its 100 directory entries list (the rest are unused entries or empty); looping ones render to the three-minute cap. Reference: ScummVM `players/player_v1.cpp` (speaker half; the PCjr half is not ported).

## v5 sounds (surveyed, not read: a large feature, deferred on 11 October 2026)

A v5 sound is not the older SCUMM sound format. `SOUN` > `SOU ` > one card part: `ROL ` (Roland MT-32, most), `ADL ` (AdLib), `SPK ` (PC speaker) or `SBL ` (digital); a sound number carries one part, the other cards use other numbers. The part holds `MDhd` and a **standard MIDI file** (`MThd`, format 2, division 480, one track; tempo in the meta event 0x51). The track also carries iMUSE system exclusives (manufacturer 0x7D) and a few Roland ones (0x41). Counts over Indy 4 and Monkey Island 2: 0x7D commands 0 (allocate a part: channel, on/off, reverb, priority, volume, pan, transpose, detune, pitch-bend range, program; the values are nibble pairs), 1 (shut a part), 2 (start of song), 16 (AdLib instrument definition), 48 (hook: jump, the most common), 49 to 53 (hooks: transpose, part on/off, volume, program, part transpose), 64 (marker), 80 and 81 (loop); manufacturer 0x41 (Roland custom instrument, about 50 to 100 per game). Reference: ScummVM `imuse/sysex_scumm.cpp`, `imuse_player.cpp`.

What it would take: a standard-MIDI reader, an iMUSE part model (on/off, volume, pan, transpose, program, pitch-bend range, loops and hooks), the Roland custom instruments as MT-32 system exclusives, and for AdLib an iMUSE AdLib MIDI driver (instrument definitions from the 0x7D 16 messages, voice allocation) on the existing OPL3 chip. The MT-32 half could reuse `ScummMt32Audio` (Munt takes short messages and system exclusives; the ROMs are in `Games/mt32`). Not started.

## Objects of v1 and v2 rooms (`ScummOldRoomObjects`)

Room header byte 20 counts the objects; from byte 28 a word per object to its image (0, or at or past the first object code: none), then a word per object to its code (the same in v1 and v2). Code: word at +4 the global object number, +7 x and +8 (low seven bits) y in units of 8 pixels, +9 width in units of 8, +13 height (multiple of 8), +14 the name offset. The image is the room picture's format at the object's size: **v2** the column-by-column run stream (a dither run copies the pixel to the left on screen); **v1** a tile-character grid read **row by row**, then a colour byte per tile, both streams using the *first* stream's four common bytes, then a mask stream (not read); drawn with the room's characters and colours. ScummVM paints objects from the last down to the second (the first is never drawn), and in these versions only those whose state has bit 3 set; the initial state is the high nibble of the object's byte in `00.LFL` (low nibble: owner, `0xF` = in the room). The explorer paints those objects over the room and shows the name (the string at the code's own offset in byte 14, plain characters; a Spanish accent is a code of its own, e.g. `]`) as a tooltip over a drawn object. Most of what looks like an object in a room (posters, speakers) is part of the background picture. Not read: verbs, masks, other states.  

## Walk boxes (checked against ScummVM `boxes.cpp`)

- **v1/v2:** byte 0x15 of the room header is the offset of a count byte; each box is 8 bytes: upper y, lower y, upper-left x, upper-right x, lower-left x, lower-right x, mask, flags. Units: x in 8 pixels, y in 2 pixels (`V12_X_MULTIPLIER`, `V12_Y_MULTIPLIER`). Matrix not read.
- **Old v3 (LOOM, Indy3 EGA) and the 256-colour Indy:** 18-byte boxes (four signed word corner pairs ul, ur, lr, ll; mask; flags), then the matrix. **v4 (Monkey Island, LOOM CD):** the `BX` block, count byte then 20-byte boxes (the 18 bytes plus a scale word). **v5:** `BOXD`, count word then the same 20-byte boxes; the matrix is the separate `BOXM`. Box 0 of the v5 games has all corners -32000.

## Scripts of v1 and v2 (`ScummScriptDisassembler.V2.cs`, `ScummOldScripts`)

ScummVM `script_v2.cpp` (`setupOpcodes`, the `o2_*` functions, `decodeParseString`) and `room.cpp` (`setupRoomSubBlocks`, version 2 and below), 12 October 2026. The opcode byte keeps the parameter bits of v3 (0x80, 0x40, 0x20 make parameter 1, 2, 3 a variable), but a variable and a result variable are **one byte**; 32 rows of eight handlers give the opcode (the table is in the source file). A print is the actor byte (unless `printEgo`) and then the text up to a zero: a byte with bit 7 set is followed by a space, 1 to 3 are text controls, 4 to 7 take another byte. `verbOps` reads a verb byte (0 delete: slot; 0xFF on/off: verb, state; else x, y, slot, preposition, then the **verb name as a string**, padded with `@`). A global script is a size word, two header bytes and the code; a room's exit script starts at the word at byte 0x18 and its entry script at 0x1A (to the room's end); an object's code has a 15-byte header (name offset at byte 14) and (verb, offset) byte pairs up to 0, with offsets counted from the code start.

## Scripts of v5 (`ScummScriptDialect.V5`, `ScummV5Archive`)

The v4 operand forms (word variables with the 0x2000 indexing flag, vararg lists, sub-opcode print, verbOps and so on; see the dialect notes in `ScummScriptReader`) with the v5 changes: `actorOps` sub-opcodes are the plain numbers (1 costume ... 23 shadow), opcodes 0x0F and 0x8F are `getObjectState` (result, object word) and `ifState`/`ifNotState` no longer exist. Blocks (all inside the room's `LFLF` except `SCRP`, which the `DSCR` directory places in the room named there): `SCRP` (global script, code from byte 8), `ROOM` > `ENCD`, `EXCD` (code from byte 8), `LSCR` (byte 8 is the script number, code from byte 9), `OBCD` > `VERB` (from byte 8: (verb, word offset) pairs ending in 0; **offsets count from the start of the VERB block**; the scripts are in the same block and may jump back into earlier code, so a verb is decoded from the whole block starting at its offset). A talkie line carries `FF 0A xx xx` speech-sample codes.
