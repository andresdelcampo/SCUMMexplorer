# SCUMM boot sequence by version

How each SCUMM version starts: which script the engine runs first, which engine variables it sets before that, and the order in which room, entry and exit hooks run. **One section per SCUMM version**; each statement carries its ScummVM source file and the date it was read. What a *game* puts into those variables is in the game's script map (`docs/<game>/<GAME>_SCRIPT_MAP.md`), not here.

Section format (copy for a new version):

```markdown
## SCUMM vN (games: …)
- **Boot script:** number, and where ScummVM starts it (`file`, function), date.
- **Variables set by the engine before the boot script:** table (slot, name, value, source).
- **Order on a room change:** exit hook, … entry hook, … (source).
- **Frame loop:** what runs per frame (source).
- **Differences from the previous version.**
```

## SCUMM v3 (LOOM EGA, Indiana Jones and the Last Crusade EGA)

Sources: ScummVM `engines/scumm` `scumm.cpp`, `vars.cpp`, `script.cpp`, `script_v4.cpp`, `script_v5.cpp`, `room.cpp`, `object.cpp`, `sound.cpp`, `players/player_ad.cpp`, read from the `master` branch on 14 October 2026 (S4b, Indiana Jones and the Last Crusade EGA). What a game puts into these variables: [LOOM_SCRIPT_MAP.md](../loom/LOOM_SCRIPT_MAP.md), [INDY3_SCRIPT_MAP.md](../indy3/INDY3_SCRIPT_MAP.md). The generic session that follows this sequence: [S4a record](../../.verification/session-generalisation-20261014/README.md), `ScummGameSession` (Core/Scumm/Session).

- **Boot script:** indexed script 1, started by `ScummEngine::runBootscript` (`scumm.cpp`) with argument 0 (`_bootParam`); only Maniac Mansion's demo uses 9. It runs inside the first frames of `scummLoop`.
- **Variables set by the engine before the boot script** (`vars.cpp`, `resetScummVars`, `setVideoModeVarToCurrentConfig`, `setSoundCardVarToCurrentConfig`): every variable is 0, then `VAR_SOUNDCARD` (var 48: 0 PC speaker, 1 Tandy, 2 CMS, 3 AdLib, 4 Roland), `VAR_VIDEOMODE` (var 49: 13 EGA, 19 VGA, 4 CGA), `VAR_CHARINC` (var 37) = 4; `VAR_HEAPSPACE` (var 40) = 1400 for LOOM and v4+; LOOM DOS also var 39 = 80. The slot numbers are the table in the [script reference](SCUMM_SCRIPT_MAP.md).
- **Order on a room change** (`room.cpp`, `startScene`): the current script ends if room-owned; `VAR_NEW_ROOM`; exit hook `VAR_EXIT_SCRIPT`, the room's exit script, `VAR_EXIT_SCRIPT2`; scripts and resources of the old room are killed (`killScriptsAndResources`); every actor is hidden; palettes reset; `VAR_ROOM` and the camera are set; then `VAR_ENTRY_SCRIPT`, the room's entry script, `VAR_ENTRY_SCRIPT2`. **Room 0** is a room with nothing in it: the exit sequence runs, `VAR_ROOM` is 0, there are no objects, and no entry sequence runs. Pseudo rooms (numbers from 0x80, filled by `pseudoRoom`) load the real room named in `_resourceMapper`.
- **Frame loop** (`scummLoop`): `VAR_TIMER` = jiffies, `VAR_TIMER_TOTAL` and `VAR_TMR_1..3` += jiffies (non-Macintosh Indiana Jones 3 also adds to variables 39 to 41); script delays count down by at most 15; `processInput`; `updateScummVars`; `Sound::updateMusicTimer` (`VAR_MUSIC_TIMER` = the music engine's timer times `_timerFrequency` / 240, 1193182 / 5041 = 236.7 Hz for DOS v2 to v4); `runAllScripts`; `checkExecVerbs` (calls `VAR_VERB_SCRIPT`); `checkAndRunSentenceScript` (pops the **last** sentence the scripts queued with `doSentence` and runs `VAR_SENTENCE_SCRIPT` with verb and the two objects as locals 0 to 2, unless a copy of that script runs unfrozen); then actors walk and the camera moves.
- **Opcodes the boot needed** (v3 shares `ScummEngine_v4`/`v5` code): `pickupObject` (`script_v4.cpp` `o4_pickupObject`): ignored for an object the room lacks or one already in an inventory, else the object goes into the `_inventory` array (80 slots, first free), its owner becomes `VAR_EGO`, class 24 (untouchable) is set, state 1, the draw queue is cleared and the script in `VAR_INVENTORY_SCRIPT` runs with 1. `getInventoryCount`/`findInventory` read `_inventory` (not the owner table); `setOwnerOf` with owner 0 frees the slot. `getVerbEntrypoint` finds the first verb-table entry equal to the verb or 0xFF. `doSentence 0xFE` returns before reading its objects. `saveVerbs`/`restoreVerbs`/`deleteVerbs` (`o5_saveRestoreVerbs`) move verbs under a save id that `getVerbSlot(verb, 0)` does not find. `waitForSentence` waits while a sentence is queued or the sentence script is in use. v3 Indiana Jones `waitForActor` breaks while the actor is in the room and moving.
- **Music timer by device** (`sound.cpp`, `scumm.cpp` `setupMusic`): DOS Indiana Jones 3 or LOOM with AdLib uses `Player_AD`: the engine timer goes up once every 121 steps of a counter that adds the song's tempo each 472 Hz callback and steps at 473 (LOOM, tempo x2) or 256 (other games, tempo x1); it is reset by `startMusic` only, so it keeps its value after a song ends. With PC speaker or PCjr it is `Player_V2`'s `_music_timer` (not modelled by the explorer). Roland goes through iMuse (markers, 0 when no song plays).
- **A script that loads a room is still running while the room is entered** (S5, 14 October 2026; `script_v5.cpp` `o5_loadRoom` calls `startScene` inside the script's own opcode, `room.cpp` `startScene`): the room's entry code asks `isScriptRunning` of the loading script and gets "running". Indiana Jones 3's Room 6 entry guards its costume change and the Donovan scene (Script 73) with `isScriptRunning 1`, so during the boot's own `loadRoom 6` neither runs. (S4b's session answered "not running" there and left Script 73 pending: a session bug, fixed in S5.)
- **`o5_loadRoomWithEgo`** (`script_v5.cpp`): `ego->putActor(room)` keeps the ego's x and y, so the entry code of the room reads the position the previous room left it at; after `startScene` the ego is put at the object's walk point unless the entry script placed it, the camera takes its x and follows it, and a walk starts if the instruction names one.
- **`setCameraFollows(actor)`** (`camera.cpp`): when the actor is not in the current room, `startScene(actor's room)` loads that room. A visit to a room that does not put the ego there makes a script that follows the ego load the ego's room (seen in Indiana Jones 3 Rooms 18, 78 and 80 through Script 23; the session does not model that load and says so).
- **Debugger `room N`** (`debugger.cpp`, `Cmd_Room`): sets the ego's room, stops all sounds and calls `startScene(N, nullptr, 0)`; the same kind of visit as the explorer's visit without a route (`ScummGameSession.VisitRoom`). The explorer additionally brings the ego in as one decoded `loadRoomWithEgo` would, as a labelled pick.
- **Differences from the previous version:** none (first documented v3 section). v4 adds variables 27, 39 and 50 to 53; v5 numbers 56 to 72 (`vars.cpp`).

## SCUMM v4 (LOOM CD, Monkey Island floppy, Indiana Jones 256 colours)

Sources: ScummVM `engines/scumm` `vars.cpp` (`setupScummVars`, `resetScummVars`, `setVideoModeVarToCurrentConfig`, `setSoundCardVarToCurrentConfig`), `script_v5.cpp` (`o5_actorOps`), `camera.cpp` (`setCameraFollows`), `sound.cpp` (`updateMusicTimer`), `scumm.cpp` (`setupMusic`), read from the `master` branch on 14 October 2026 (S4b, Monkey Island floppy). What the first game puts into these variables: [MONKEY1_SCRIPT_MAP.md](../monkey1/MONKEY1_SCRIPT_MAP.md). The generic session that follows this sequence is `ScummGameSession` (Core/Scumm/Session); the record is [monkey1-session-20261014](../../.verification/monkey1-session-20261014/README.md).

- **Boot script:** as in v3 (indexed script 1, argument 0, started by `runBootscript`); nothing in the files read differs for v4.
- **Variables set by the engine before the boot script** (`vars.cpp`): as v3, plus for version 4 and later `VAR_HEAPSPACE` (var 40) = 1400, `VAR_FIXEDDISK` (var 51) = 1 and `VAR_DEBUGMODE` (var 39) = 0 (no debug mode); `VAR_VIDEOMODE` is 19 for VGA, 13 for a 16-colour (EGA) render mode, 4 CGA. Every global variable is allocated zeroed (800 of them for these games), so a variable no script has written reads 0. The slot table is in the [script reference](SCUMM_SCRIPT_MAP.md); `ScummProfile.EngineVariablesAtStart` and `GlobalVariableCount` carry these values.
- **Order on a room change:** as v3. `setCameraFollows` (camera.cpp, `actorFollowCamera`): when the actor is not in the current room, `startScene` of the actor's room runs first, then `camera._cur.x` is the actor's x and the camera follows it. Actor 0 is a valid slot of the actor array that is never in a room, so following it starts room 0.
- **Frame loop:** as v3, with the music timer by music engine: `Sound::updateMusicTimer` (sound.cpp) sets `VAR_MUSIC_TIMER` from the music engine's `getMusicTimer()` times the timer frequency over 240, or from the CD timer for games with audio tracks. `setupMusic` (scumm.cpp) uses `Player_AD` for DOS AdLib only for LOOM and Indiana Jones 3; **Monkey Island floppy with AdLib goes through iMuse** (the generic `IMuse` path), so the explorer's AdLib music timer for it (the song's `AD` block played by `ScummAdlibAudio` at the browsed disks' half tempo, S3's decision made by ear) is an **estimate**, not the engine's own timer.
- **What a music start stops** (read 16 October 2026, S6 sound; v3 and v4): `Player_AD::startSound` (LOOM, Indiana Jones 3) treats a resource whose byte 2 is 0x80 as music and calls `stopMusic()` first (one music slot; effects take one of three slots by priority and are dropped when all hold a higher one). Through iMuse, `Sound::triggerSound` stops **all** sounds before any resource that is not `ASFX` for Monkey Island EGA/VGA only ("the music is never explicitly stopped"); `convertADResource` makes an AD block with 0x80 an `ADL ` song (looping unless its loop flag is set) and any other an `ASFX`. `soundKludge` only queues iMuse commands (none of the three played v3/v4 games uses it). `isSoundRunning` answers the mixer, the queue, then the music engine's `getSoundStatus`. Carried by `ScummProfile.MusicStart`.
- **Opcode differences met by the boot** (`script_v5.cpp`): `o5_actorOps` case 17 (scale) reads one value in version 4 (two later). `actorFollowCamera` as above.
- **Differences from the previous version:** several disks (`DISK01.LEC` to `DISK04.LEC`, each an XOR 0x69 archive; the index `000.LFL` is shared and names for every resource the room that holds it, so a resource's disk is the disk of its room); the game asks the player to change disks (not modelled: all disks are assumed inserted, R-3.15); script 1 may wait for the player (R-15.7).

## SCUMM v5 (Monkey Island 1 CD, Monkey Island 2, Indiana Jones and the Fate of Atlantis)

Sources: ScummVM `engines/scumm` `vars.cpp` (`setupScummVars`, `resetScummVars`, `ScummEngine_v5::resetScummVars`), `script_v5.cpp` (`setupOpcodes`, `o5_drawObject`, `o5_pickupObject`, `o5_actorFromPos`), `sound.cpp` (`updateMusicTimer`), `soundcd.cpp` (`playCDTrackFromSoundID`, `playCDTrack`, `cdTimerHandler`, `startCDTimer`/`stopCDTimer`), read from the `master` branch on 17 October 2026 (S4b, Monkey Island CD). What the first game puts into these variables: [MONKEY1_SCRIPT_MAP.md](../monkey1/MONKEY1_SCRIPT_MAP.md), CD section. Record: [monkeycd-session-20261017](../../.verification/monkeycd-session-20261017/README.md). Monkey Island 1 CD and Monkey Island 2 have been booted; Indiana Jones 4 is not checked against this section here.

- **Boot script:** as in v3 and v4 (indexed script 1, argument 0). Resources come from `NAME.000` (index: `DROO DSCR DSOU DCOS DCHR DOBJ`) and `NAME.001` (the `LFLF` rooms), XOR 0x69 ([formats](SCUMM_RESOURCE_FORMATS.md)); local scripts are numbered from 200. The object table at start is `DOBJ`: a count word, a byte per object (owner low nibble, state high nibble), a class dword per object.
- **Variables set by the engine before the boot script** (`vars.cpp`): as v4 (`VAR_HEAPSPACE` 1400, `VAR_FIXEDDISK` 1, `VAR_DEBUGMODE` 0, 800 zeroed globals, `VAR_VIDEOMODE` 19 for VGA, `VAR_CHARINC` 4, `VAR_CURRENT_LIGHTS` 11), plus `VAR_INPUTMODE` (var 67) = 3 (mouse), `VAR_FADE_DELAY` (var 59) = 3, and from `ScummEngine_v5::resetScummVars` `VAR_V5_TALK_STRING_Y` (var 54) = -0x50 (versions 4 and 5) and, for `GID_MONKEY` (the CD release, not the floppy `GID_MONKEY_VGA`), `_scummVars[74]` = 1225 (no comment in the source). The v5 slots 56 to 72 are named in the [script reference](SCUMM_SCRIPT_MAP.md). Carried by `ScummProfile.EngineVariablesAtStart` (version 5 only; the explorer does not yet set var 54 for the v4 games).
- **Music timer of a game with audio tracks** (`GF_AUDIOTRACKS`): `Sound::updateMusicTimer` copies the CD timer into `VAR_MUSIC_TIMER` every frame. `playCDTrackFromSoundID` reads the sound's `SOUN` block (track byte, loop count, start and end as minutes/seconds/frames at 75 per second; end not after start = to the end of the track; loops 0xFF = for ever) and `playCDTrack` sets `VAR_MUSIC_TIMER` and the CD timer to 0 and installs `cdTimerHandler`, which adds one every fourth tick of the engine's 240 Hz timer (one per jiffy). Only `stopCDSound`/`stopAllCDSounds` remove the timer; a track that ends on its own leaves it counting. One track plays at a time. Monkey Island 1's track 17 start can be shifted by a user setting (`start += 75 * adjustment / 100`; the explorer uses no shift). Carried by `ScummCdAudioTracks` and `ScummGameSession` (data-driven: any v5 game with track sounds on a disc image).
- **Opcode differences met by the boot** (`script_v5.cpp`): 0x05/0x45/0x85/0xC5 are `o5_drawObject` with a sub-opcode (low five bits: 1 position x, y; 2 state; 0x1F neither), and **0x25/0x65/0xA5/0xE5 are `o5_pickupObject`** (object word, room byte, 0 = current room), where the small-header games read all eight as the three-operand drawObject; `o5_pickupObject` checks neither the room nor the owner and sets class `kObjectClassUntouchable` (32, no small-header translation). 0x50/0xD0 (`pickupObjectOld`) are not registered in v5. `o5_expression`'s nested opcodes include `getInventoryCount` (Monkey Island CD's inventory script, Script 9).
- **Differences from the previous version:** one resource file instead of disks; music on CD audio tracks (Monkey Island CD) instead of AdLib/iMuse songs for the timer; the opcode table above. Monkey Island CD's boot asks for no input (no copy-protection room) and ends at the lookout (Room 38) with the player in control while the opening's track plays.
- **Monkey Island 2 (S4b Monkey2, 17 October 2026; `mi2 talkie en`):** boot parameter 0 (ScummVM sets -7873 only for the Mac release and Indy 4; the game's Script 1 treats -7873 as 0). The boot uses `o5_soundKludge` from its first instructions (the word list goes to iMUSE `doCommand`, `imuse.cpp` `doCommand_internal`: low byte the command, high byte 0 the sound engine or 1 a playing song's player; `Sound::processSoundQueues` writes the answer to `VAR_SOUNDRESULT`; a `[-1]` list processes the queue at once), `roomOps` sub-opcode 4 in its big-header form (r, g, b words, a second sub byte, the palette index), and `roomOps loadString` of a missing `monkey2.cfg` (the string stays as written). It waits in Room 108 for the "Monkey Island 2" / "Monkey 2 Lite" choice (Script 130, answered through the input script Script 131) and reaches the player's first control at the campfire, Room 4. v5 object images are one `IMnn` per state, and strips with a transparent codec skip the room's `TRNS` colour. Record: [monkey2-session-20261017](../../.verification/monkey2-session-20261017/README.md).
