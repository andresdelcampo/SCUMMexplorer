## B. Inconsistencies (code ↔ docs, edition ↔ edition)

| I-01 | Med | Read | **EGA and CD cutscene titles are built by different rules.** EGA catalog titles (generated, then rewritten at load) read `Use response`, `Look response`, `Walk response`, and `Use sheep`, `Use gate` for the same kind of trigger. The CD path always builds `Use <object>` / `Look at <object>` / `Walk to <object>` unless the source loads rooms. ## C. Risks

| ID | Sev | Conf | Finding | Req |
|---|---|---|---|---|
| K-01 | Med | Read | **Done 10 Oct: hashed in parallel (~25 ms), draw batches built once on a worker.** **Catalog fingerprinting hashes 78 files synchronously on the UI thread** every time a LOOM EGA folder is opened (`LoomReplayCatalog.Load` is called from `OpenGameFolder`). It stops at the first mismatch, so other editions are cheap, but the reference edition reads every `.LFL`. Probably tens of ms on an SSD, but it is avoidable blocking on a hot path. Move to a background task or cache by folder timestamp. | R-8.18 |
| K-02 | Med | Read | **Parked 10 Oct, pending M-01 (handled in a parallel task):** a script-derived list for editions whose fingerprint does not match removes most of the problem. Revisit only for the near-match case (keep the validated reference scenes when one unrelated file differs); options then: per-recipe file lists (needs one discovery rerun on the reference edition with file-read logging) or a cached runtime check that each recipe still reaches its recorded rooms/frames. **Replay catalog is all-or-nothing.** One changed byte in any of 78 files (for example a v1.2 patch to a depth mask, which the editions record shows is harmless to the app) disables all 328 replays for that edition. The decision not to rerun discovery per edition is yours (5 Oct); the narrower point here is that the fingerprint could cover only the files a recipe actually reads, so an unrelated file does not disable unrelated scenes. | R-8.18, R-8.19 |
| K-03 | Med | Read | **Done 10 Oct: titles are in Core and pinned by tests.** **Titles and picker logic cannot be unit-tested.** Cutscene title formatting (`LoomReplayTitle`, `LoomDraftNames`, `CdCutsceneTitle`, `PickerVerbTitle`) lives in the App project; the test project covers Core only. The title formats in R-8.6… are therefore guarded by no automated test. Moving the pure string logic to Core (`Loom/Scenes` or `Loom/Text`) lets tests pin the formats. | R-8.x |
| K-04 | Med | Read | **Partly done 10 Oct: the cutscene section moved to MainWindow.Cutscenes.cs; Core files not split.** **Very large files.** `MainWindow.xaml.cs` ≈ 5 990 lines, `ScummBoundedScriptExecutor` ≈ 2 835, `LoomExplorationSession` ≈ 2 760. Review, merge and test cost grow with that; the cutscene section (≈ 400 lines, 3900–4300) and the tree/catalog code are natural partial-class or Core extractions (`MainWindow.CostumeCards.cs` already shows the pattern). | R-16.1 |
| K-05 | Low | Read | **Done 10 Oct: LoomResourceNames and LoomVerbNames in Core/Loom/Text; LoomStatusPresentation (WPF bitmaps) and LoomEgaStateFlags (needs App types) stay.** `LoomDraftNames`, `LoomVerbNames`, `LoomResourceNames`, `LoomStatusPresentation` and `LoomEgaStateFlags` are `LOOM`-generic or `LOOM EGA` but live in the App project, against the rule "put code in the lowest layer that is true for it". `LoomDraftNames` even says CD uses it. Naming and layering tidy-up. | R-3.6, R-16.1 |
| K-06 | Low | Read | **Done 10 Oct: scan is Loom/Scenes/LoomCutsceneIndex (types LoomCutscene, LoomCutsceneGroup).** `LoomCutsceneIndex` works only through `IScummDataSource` and generic opcodes (`cutscene`, `print`, `loadRoom`), but sits in `Loom/Cd` and its `VerbLabel` hard-codes LOOM's 0x36/0x37/0x38. The scan itself is `SCUMM` generic and could serve the EGA path too (see M-01). | R-8.21 |
| K-07 | Low | Likely | **Dropped by the user 10 Oct.** `view-options.txt`, `last-folder` and cache files are unversioned plain text/`key=value`. An older build reading a newer file ignores unknown keys (good) but a future change of meaning of an existing key would not be detected. Fine for now. | R-4.8 |
