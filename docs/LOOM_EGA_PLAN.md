# LOOM EGA exploration plan

## Product direction

Make the supplied DOS *LOOM* EGA release feel like a place to explore: rooms and their original artwork lead; visible exits and objects invite clicks; meaningful draft actions can change the displayed world; original sound is available where the game data supports it. Keep source details available on demand so the main view remains understandable without SCUMM knowledge. Later, add scene playback and a discoverable, evidence-backed guide to secrets.

The target view starts with a room viewport showing up to 320 source pixels across, scaled to use the available area, with horizontal browsing for wider rooms and an option to show the full panorama. Sound controls sit centered below the room. Clicking an object opens a compact contextual card with source-supported draft choices, before/after state thumbnails, and reset or undo for previews. A room picker or map helps browsing. A supported scene can be played or replayed. Costume inspection shows all decoded static poses together at the same enlarged scale; true animation needs decoded sequence and timing evidence. The resource tree, raw IDs, and script evidence stay collapsed until requested. Unsupported actions explain the missing condition briefly instead of presenting an inert click target.

This is a product plan, not a claim of complete gameplay emulation. The [exploration audit](EXPLORATION_AUDIT.md) and [object-state notes](SCUMM_OBJECT_STATES.md) remain the technical record. Their 25 September 2026 counts and checks are historical audit results; the 25 September planning pass did not repeat runtime validation. ### 27 September 2026 exit result and correction

The [Room 03 exit validation](../.verification/room03-exit/validation.md) records the full trace.

- Under SCUMM's `jumpRelative` rule, a conditional branches when its condition is false, so `equalZero x → back` loops while `x` is nonzero. Local script 200 +0x0001 therefore waits while bit `0xD7A` is set. Script 42 +0x0021 waits while `var[0x003]` (a message on screen) is nonzero.
- Script 42 sets `0xD7A` while its actor 2 is on screen (+0x0058 to +0x0091). The Room 03 entry starts script 42 only when bits `0xD62` and `0xD6E` are 0. Script 001 +0x015B sets `0xD62` at boot, so on the session's boot state script 42 does not run and the bit is 0.
- The only missing piece was `stopScript 0x2A` at local 200 +0x0006. It is now modelled after ScummVM: stopping a script that is not running does nothing. Loads reached by continued scripts are now dispatched.
- Object 162 → Room 04 and object 167 → Room 03 are reached as exploration actions on a state preview.

## Evidence and status rules

For each exit, object action, draft result, state change, sound cue, and eventual scene or secret, link the LOOM EGA resource, script, instruction and condition that support it. Describe what the source establishes and what remains inferred. A decoded conditional branch or room-load instruction is a **possible** outcome; direct invocation of a verb is an **exploration action**; a partial bounded session is a **state preview**. Call something gameplay execution only when the necessary input selection, state, conditions, sequencing, and resulting changes are actually modeled and verified. Do not fill gaps with room-specific behavior exceptions or erase a verified source glitch.

Keep progress here rather than rewriting reverse-engineering notes.
