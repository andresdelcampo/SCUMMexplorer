# LOOM EGA script map

A working reference for the Spanish DOS LOOM EGA data in `Games/loom`: what the decoded scripts do, which variables they use, and how the session models them. Offsets are into each script's code, as `CodeDump` prints them (`.verification/fallback-evidence/code.tsv`, regenerated with `dotnet Exe/CodeDump/.../CodeDump.dll Games\loom .verification\fallback-evidence`). Each entry says whether a claim is **decoded** (read straight from instructions), **ScummVM** (engine behaviour checked against `engines/scumm`), or **reading** (an interpretation that has not been verified in a run).

Last updated 28 September 2026 (M1a: messages, talk delay and `waitFor message` modelled; charset 0 read). See also [the plan](LOOM_EGA_PLAN.md), the [changelog](CHANGELOG.md), the [boot validation](../.verification/boot/validation.md) and the [cutscene continuation validation](../.verification/cutscene-continuation/validation.md).

## Verbs (decoded; ScummVM `o5_verbOps`, `verbs.cpp`; modelled 28 September)

- Room 01 local 211 (the intro, on the boot route) creates the verb bar: `verbOps N, [new; at x, 144; image obj; off]` for verbs 0x01–0x35 (images from Room 01 objects 100–151; verbs 0x01–0x08 at x 16–192 are the distaff notes, the others share those positions) and `new` for verb 0x36, the close-up slot, later put at (248, 152).
- Scripts 018 (turns verbs 0x01–0x08 on at `local[4]`'s y, and 0x31/0x32), 019 (turns them off), 027/028 (verb 0x35), 031 and 008 change them later.
- ScummVM facts the session follows: `getVerbSlot` returns 0 for a verb with no slot, and `image` is ignored there; `setVerbObject` takes the image only when the object is one of the current room's objects.
- The verb area is screen rows 144–199 (the boot's `initScreens(0, 144)`, see Screen rows). `drawVerbBitmap` draws an image verb that is on or dim at `x / 8` strips, `height / 8` strips down, and sets its `curRect` to the verb's x, y and that size; `findVerbAtPos` takes the last slot in mode 1 whose `curRect` holds the point. ## Messages, charset and actor commands (decoded counts; ScummVM references for milestones M1–M3)

- **`print actor, [subops]`** (1,170 sites). Actor operand: 0x01 (the ego, 453), 0x02–0x0B (other actors), 0xFF (173; ScummVM: no actor, a system line), 0xFE (74; script 018's note letters). Subops: `text` (1,170), `center` (1,037), `position x, y` (439; y is often `var[0x0A6]`), `color` (154), `height` (6; ScummVM reads the line height for subop 6 in v3, which later versions use as `SO_LEFT`; the disassembly said `left` before 28 Sep). Text control codes in print texts: `0xFF 0x01` new line (683), `0xFF 0x07` a string (10), `0xFF 0x04` a number (2), `0xFF 0x06` a name (2) (decoded counts); `@` is a filler that is not drawn (ScummVM `convertMessageToString`).
- **Text slots** (ScummVM `decodeParseString`): actor 0xFE uses slot 1 (`drawString`: drawn at once, no delay, stays until the room is redrawn), 0xFD slot 2 (a debug message), 0xFC slot 3 (a message dialog), every other value slot 0 (`actorTalk`). Each print starts from the slot's defaults, and v1–v3 keep the position, height and colour as the defaults afterwards, but not the centring. So a print with no position uses the last print's (ScummVM notes that LOOM needs this). Defaults at the start: (0, 0), height 0, colour 15, right edge 319.
- **Talk** (ScummVM `actorTalk`, `displayDialog`, `stopTalk`, v3): a print for an actor who is not in the current room shows nothing.
