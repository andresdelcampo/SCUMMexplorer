# LOOM VGA (CD) feasibility probe, step 1 (5 October 2026)

**Pictures** (contact sheets, room01/room02, `window-check/*.png`) are made locally and are not in git (`.gitignore` skips `.verification/**/*.png`); rerun `decode_rooms.py` and `CdCheck` to recreate them. Read-only. Scripts: `iso_extract.py <Loom.bin> <outdir>` (ISO 9660 over `MODE1/2352` raw sectors: user data at byte 16 of each 2352-byte sector) and `probe.py <outdir>` (block tree). Extracted files go to a scratch folder, never into the repository.

## The two discs

| | `Games/loom vga en` | `Games/loom vga en kixx` |
|---|---|---|
| Image | `Loom.bin` + `Loom.cue` | `LOOMCD.BIN` + `LOOMCD.CUE` (renamed back, 5 October, so the cue matches its bin) |
| Volume label | `LOOM` | `LOOMCD` |
| Track 2 (CD audio) starts | 04:57:60, pregap 2 s | 04:58:00, pregap 2 s |
| Data files | `000.LFL`, `901`–`904.LFL`, `DISK01.LEC`, `LOOM.EXE` | the same seven |

**All seven data files are byte-identical between the two discs.** They differ only in the label, the disc layout (LBAs) and the audio track's start (a few frames), so one game reading serves both; the audio offsets are per disc (read them from the `.cue`).

## File formats (SCUMM v4)

- **`DISK01.LEC`**, 4,059,462 bytes, **XOR 0x69** over the whole file. A block is `size u32 LE (header included)`, a two-letter tag, the body. `LE` holds `FO` (room offsets: a count byte, then room u8 + offset u32 per room) and **78 `LF` room blocks** (`LF`: room number u16, then `RO` room image data, `SC` scripts, `CO` costumes, `SO` sounds).
- Room-level counts: 78 `RO`, 122 `SC`, 166 `CO`, 30 `SO` (2 stray two-byte blocks at the end of a room are padding, to confirm).
- Inside `RO` (room 1 as the example, 320 x 200): `HD` header (width, height, object count), `CC` colour cycles, `SP` (unknown, 262 bytes), `BX` walk boxes, **`PA` a 256-entry VGA palette** (776 bytes), `SA` scale slots, **`BM` the 256-colour background** (compressed strips, 22 KB for room 1), `OI` one object image per object, `NL`/`SL` counts, `OC` object code and name (21 bytes each here), `EX`/`EN` exit and entry scripts, `LC` count and **`LS` local scripts** (the VGA game keeps its scripts in the room, as EGA does).
- Totals over all rooms: backgrounds (`BM`) 2.0 MB, object images (`OI`) 0.7 MB, local scripts (`LS`) 87 KB, entry scripts 11 KB.
- **`000.LFL`**, the index: plain (not XORed) blocks `RN` room names (room number then a 9-byte name XOR 0xFF), `0R` rooms, `0S` scripts, `0N` sounds, `0C` costumes (each: count u16, then count x (file/room u8, offset u32 LE)), `0O` objects (1000 entries). Script, sound and costume entries give the room and the offset inside that room's `LF`.
- `901`–`904.LFL` are the charsets (not decoded). `LOOM.EXE` is the game's own executable (117 KB).

## What this means for the plan

- Reading the files is straightforward: the `.LEC` XOR and block tree are simple, and the index is small. The **disc image reader** is the easy part (a few dozen lines; the user data of a Mode 1 sector is bytes 16 to 2063).
- **Not decoded yet** (the next steps of the plan, none of it touched): the `BM` strip codec (v4 VGA bitmap, to take from ScummVM `engines/scumm` `gfx.cpp` `drawStripComplex`/`drawStripBasicV` family and compare with the `scummvm/` build), `OI` object images, the v4 script dialect (the EGA `LoomScriptReader` is v3), costumes and sounds (30 `SO`; the music and speech are CD audio on track 2), `SP` and `CC`.
- The Game Status, glossary and replay catalog are EGA-derived and are not reused for VGA (the plan says to rederive, never copy); VGA starts with rooms and backgrounds.

## Step 2: the room background decodes (5 October)

`decode_rooms.py` (Python, scratch-only; the Core port comes next) decodes **all 78 room backgrounds** without an error, checked by eye on the contact sheet [all-rooms-contact-sheet.png](all-rooms-contact-sheet.png) and on [room01.png](room01.png) (the LucasArts logo) and [room02.png](room02.png) (960 x 144 scrolling mountain view).

- **Palette:** `PA` body = `u16 768`, then 256 RGB triples (8-bit, used as they stand), then 6 trailing bytes.
- **`BM`:** the body is `u32` (the data size), then one `u32` offset per 8-pixel-wide strip (width / 8 entries; offsets are from the start of the body), then the strips. A strip begins with a code byte: `0x01` raw (8 columns of height bytes, column by column) or `0x0E`–`0x12` / `0x18`–`0x1C`, the ScummVM "basic" run-less bit codec, vertical (`0x0E`–`0x12`) or horizontal (`0x18`–`0x1C`); the code modulo 10 is the colour bit count (here always 8). Bits: `0` same colour, `10` read a new colour (that many bits), `110` colour += step, `111` reverse the step then colour += step; the step starts at -1. Only codes `0x01`, `0x12` and `0x1C` occur in this game.
- A few rooms show black on the sheet (the dark rooms and the close-up boards); they may be fully dark or use features not decoded yet (`SP`, transparency or object-only rooms). Not checked.
- Room sizes: 320 x 200 for the logo, 320 x 144 for scenes, up to 960 x 144 (scrolling).

## Step 3: the scripts read with a v4 dialect (5 October)

The CD game's bytecode is the **v5 operand set** (ScummVM `ScummEngine_v4` = `ScummEngine_v5` plus a few overrides; `ScummEngine_v3`, the LOOM EGA class, derives from v4 and overrides three opcodes). The existing disassembler already read 742 of 793 scripts without an issue as plain LOOM EGA; a new dialect `ScummScriptDialect.LoomCd` (`ScummScriptDialects.For(GameId.LoomVga)`) brings that to **all 793** (global `SC`, entry `EN`, exit `EX` and local `LS` scripts of the 78 rooms), checked by the test `EveryScriptOfTheCdGameDecodesWithTheV4Dialect`. What differs from the EGA dialect, from ScummVM `script_v5.cpp` (read as reference; the code is our own):

- `roomOps` (0x33): the sub-opcode byte comes first and each operand's variable bit is read from it (the EGA game reads two operand words first). Sub 2 and 4 take two words (small-header blocks), 7 scale, 8 intensity, 9 save, 10 fade, 11 and 12 RGB, 13 and 14 file-name strings, 15 transform, 16 cycle speed.
- 0x30 is `matrixOps` (set box flags, scale, scale slot, create box matrix) instead of `setBoxFlags`; 0x3B is `getActorScale` (a result and an actor) instead of the no-op `waitForActor`; 0x4C is `soundKludge` (a word list) instead of `waitForSentence`.
- `print` sub-opcode 6 has no operand (left); `cursorCommand` 14 takes a word list.
- Scripts are plain blocks, not `00.LFL` resources: `LoomVgaArchive.ReadScripts(room)` returns them and `LoomScriptReader.DecodeCode` reads the bytes.

Decoding without an issue is not the same as understanding the scripts; the executor, glossary and variables of the CD game are untouched.

## Step 4: objects and texts (5 October)

- **`OC` object blocks** (`LoomVgaArchive.ReadObjects`): id at block offset 6, x/8 at 9, y/8 at 10 (bit 7 the parent state), width/8 at 11, parent at 12, walk-to point words at 13 and 15, height and facing at 17, the name's offset at 18, then the verb table (verb byte and word offset, ended by a zero verb; 0xFF is the fallback verb), the zero-ended name and the code. The verb offsets land exactly on the code that follows the name (room 3 object 0x5F: verb 0x37 at 24, name at 23 is empty); room 4's "owl" has verbs 0x36, 0x39 and 0x56.
- **`OI` object images**: the object id (u16), then a `BM`-like body (size u32, one u32 offset per 8-pixel strip counted from the size field, strips); the width is the object's, the height comes from the `OC` block. Not decoded in Core yet. **The index's `0O` table gives every room object the same initial state (owner 0xF, state 0)**, so what a room shows at first visit comes from running its entry script (EN), as on EGA; the backgrounds already carry the permanent scenery.
- **Texts** (`LoomTextExtractor`, CD branch): 1,196 entries from 1,470 scripts (the 793 script blocks plus the object verb scripts): 1,042 spoken lines, 134 object names, 20 stored lines, nothing skipped or unresolved. The Game Texts window opens with them (room pictures from the CD data); `TextGalleryCheck` passes its first three checks (the fourth expects EGA room 3 text). The harness's search term was a hard-coded Spanish word, which is why it failed on every non-Spanish edition; it now takes a word that occurs in several texts.
- The spoken lines start and end with the control character 0x19 (the "keep text up" marker); the EGA extraction treats markers the same way.

## Step 5: costumes (5 October)

All 165 costumes the index lists (`0C`; the file has 166 `CO` blocks, one not indexed) draw: [all-costumes-contact-sheet.png](all-costumes-contact-sheet.png) shows each one's pose with most pixels (Bobbin in his robe with the distaff, the swans, the sheep, flames, the dragon, the crescent moon). Format, from the data and ScummVM `costume.cpp` (`ClassicCostumeLoader`, small-header v4): block body byte 0 the last pose index, 1 the format (0x58, 16 colours), 2 to 17 the colour-to-room-palette table, 18 the command-list offset, 20 sixteen limb frame-table offsets, 52 the pose offsets; **every stored offset counts from the start of the `CO` block including its 6-byte header**; a pose is a little-endian limb mask, then per limb a word (0xFFFF: none) and a length byte; a cel is width, height, relative x and y, move x and y, then nibble run-length data in columns. The costume's own palette is the palette of the room that stores it (the index `0C` entry says which). The directory entries (`0S`, `0N`, `0C`) are a room byte and a dword offset counted from the first block inside that room's `LF` block.
In the app: the **Costumes** tab and the pose gallery work for the CD game (`.verification/loom-vga/CdCheck`, screenshots in `window-check/`). Code: `LoomVgaCostumeRenderer`, `LoomVgaArchive.ReadCostumes` and `DecodeCostumePoses`.

## Step 6: the data-source seam and first-visit object states (5 October, night)

- **Seam:** `IScummDataSource` with `LoomEgaDataSource` (unchanged EGA reads) and `LoomCdDataSource`. `LoomExplorationSession` and `LoomSceneDrawBatches.Build` call it instead of `GameResource.FilePath`, `LoomScriptReader.Decode*` and `LoomObjectVerbReader`; the session takes an optional source. Filtered EGA tests (session, bounded executor, scene, first-visit, estimated room load, demos) passed after the move: 85 passed, 3 skipped, 0 failed on `loom ega mt32 en`. Left on the EGA readers because they are separate scanners with their own `FilePath` reads: `LoomEgoArrivalIndex`, `LoomSceneStateScanner`, `LoomGlossary`, `LoomRelationshipIndex`. They are not reached for the CD game while the session has no ego (no catalog arrival) and are the next place that needs the seam when Bobbin is put on screen.
- **CD data facts (from the data, checked by tests):** the `0S` table lists 199 slots, 122 global scripts exist, and every local script number is 200 or higher, so 200 is the local boundary (`LoomVgaArchive.LocalScriptBase`). `0O` has four bytes per object (three of class bits, then state in the high nibble and owner in the low), like the EGA index. An `OI` block is the object id then a `BM`-like body counted from its size field; width and height come from the `OC` block.
- **First-visit state:** the session runs boot script 001 (`completeBoot: false`) and a room's entry script in a fresh session (`LoomCdRoomScene.FirstVisit`). Many entry scripts first hide their objects (`setState` 0) and draw the ones they want (`drawObject`, state 1); 19 of the 78 rooms set object states, and the entry scripts of rooms such as 6, 13, 31, 53 and 55 paint objects that differ from the background. `CdCheck` renders rooms 1, 4, 13, 31, 53 and 86 (screenshots are local). Room 53 shows the cloaked figure, which only the entry script draws. Where an image equals the background under it (rooms 13 and 17), the decode is confirmed.
- **Picks:** the session's seeded picks (`getRandomNr`) are listed in its uncertainties; the app's note under the scene says how many were taken. No pick changes a state the entry script does not itself reach.
- **Not done:** walk boxes (`BX`; `ScummRoomData.WalkBoxError` says so), Bobbin and the costume source in the session, object verbs in the UI, charsets, CD audio. The transparency of object images is not established (the strips here are code 0x01/0x12/0x1C, which do not mark transparency; some images have colour-0 pixels over a non-black background in rooms 35 and 40: look at them in the real window before drawing Bobbin).

## Step 7: walk boxes, the scanners behind the seam, Bobbin on screen (5 October, late night)

- **`BX` walk boxes:** body = a count byte, then 20-byte boxes (four signed corner pairs, mask, flags, a scale word; ScummVM `BOXD` for v4/v5), then the same matrix rows as old-v3 (`LoomWalkBoxReader.ReadBlockBody`). `LoomCdDataSource.ReadRoom` returns them; the test reads all rooms (78 rooms: 1 box in many, 52 in room 30; room 16's matrix lacks the closing row of its last box, a data fact like Indy3 Room 46 on EGA; ScummVM reads on regardless).
- **Seam:** `LoomEgoArrivalIndex.Build` and `LoomSceneStateScanner` read scripts, objects and verbs through `IScummDataSource` (new `GlobalScriptIds`, `ReadCostume`); the CD game gets arrivals (for example `Room 36 Object 524 Verb 0x38` into room 35). `LoomGlossary` and `LoomRelationshipIndex` stay on the EGA readers: Bobbin does not need them (the plan says to rederive names for the CD game, not copy). Filtered EGA tests on `loom ega mt32 en` (arrivals, session, actors, scene, demos, replays, bounded executor, costumes): 113 passed, 3 skipped, 0 failed.
- **A bug found on the way:** `LoomCdDataSource.GlobalScript` set a `Context` text, and the session treats a script with a context as room-owned (`frame.Global = script.Context is null`), so script 001 never survived its own room load. Global scripts now carry no context, as on EGA.
- **The ego:** script 001 sets `var[0x001] = 1` (Bobbin is actor 1) only on the path after the intro. A first-visit session does not play the intro, so after script 001 pauses at the intro's room load (Room 69), the session runs it on from the jump target of its `equalZero local[0x000]` (found in the code, not by offset; +0x0362 here) to the room load that opens the game (Room 01). The vars the game has when the intro ends (ego, costume numbers, starting vars) are then in place; the trace says so. Then the catalog-visit machinery places Bobbin as for EGA: an assumed arrival (`LoomEgoArrivalIndex`, seeded pick, labelled, never reached game input). Rooms with no arrival (1, 40 and others) show only the actors their entry script puts there.
- **Costumes in the session:** `LoomCostume.ReadVga` (the CD costume as the EGA class's animation: header 6 bytes ahead so stored block offsets work, limb table at body byte 20, animation table at 52, a word per limb start command, a 16-entry colour table to the room palette, move start (0, 0) instead of (-72, -100)). `IScummDataSource.ReadCostume` feeds the actor table; `LoomActorLayer.IsDrawn` keeps coverage apart from `Transparent` (0xFF), because Bobbin's colour table names room palette index 255. Test: all 165 costumes read and 100+ draw a first animation.
- **On screen:** the CD room view draws the actors (`UpdateCdActorLayer`): room 35 shows Bobbin in his cloak by the window and the second actor on the wall; room 16 shows him small on the rocks; rooms 4, 10, 16 are placed too (room 4's Bobbin stands at x 580 and the CD view starts at x 0, so scroll right to see him; the view does not follow the camera yet). Screenshots are local (`window-check-step7/`, not in git).
- **Object-image transparency (rooms 35 and 40), checked in the real window:** no gaps or black rectangles around objects; the strips use codes 0x01, 0x12 and 0x1C, which are not transparent in ScummVM, so every object is an opaque rectangle and the art accounts for it. Nothing changed.
- **Not done:** a depth mask for CD actors (every actor is drawn in front), `matrixOps` in the executor (room 35 local 203 notes it), walk to a click, object verbs and clicks in the UI, charsets, CD audio, the view following the camera.

## Step 8: depth masks and the camera (5 October, late night)

- **Data check:** a room has no mask block of its own; the mask rides in the tail of the `BM` body (and of each `OI` body). The body's first dword counts the strips (room 1: 22,107 of 22,351 bytes); what follows is a word (length, itself included: 242), one word per strip (offsets from the block's start, 0 = none) and per strip the EGA mask coding (code with bit 7: repeat the next byte, else copy that many bytes; 0 means 256), one byte per row of 8 pixels. Rooms 12 and 29 have two stray zero bytes only (no mask). Room 1 (the logo) has an all-zero mask. One plane only.
- **Code:** `LoomVgaArchive.ReadMaskPlane` for both `BM` (`RoomImage.DepthMask`) and `OI` (`LoomVgaObjectImage.Mask` into `RoomObjectImage.Mask`). The app passes `_objectSelection.ComposeDepthMask(room)` to `LoomActorRenderer`, with the walk boxes' mask byte (BX) and object classes 20/21, exactly as on EGA. Tests: `TheCdRoomsCarryDepthMasks...` and `TheDepthMaskHidesPartOfAnActorBehindScenery...` (rooms where the mask hides actor pixels: 4, 16, 17, 18, 20, 22, 30, 34, 35, 37, 39, 50, 62, 63, 65, 66).
- **Camera:** the CD room view starts at `LoomCdScene.CameraX` (`_pendingCameraX`); room 4 shows Bobbin at x 580. `CdCheck` now reports the view offset (`dotnet build .verification/loom-vga/CdCheck` first: it is not in the solution).
- **Not done:** `matrixOps` in the executor; verbs and clicks (gate proposal pending the user); charsets; CD audio.
